# 提交并推送已修改的文件至远端仓库

## 前置检查（只读）

1. `git status` 确认待提交文件清单（目前已知：`CHANGELOG.md`、`tools/extract-release-notes.mjs`、`webview/src/version/githubReleases.ts`、`webview/src/version/githubReleases.test.ts`，以及用户本地可能存在的 `src/host/handlers/FontConfigHandler.ts`、`webview/src/styles/less/base.less`）
2. `git fetch origin` + `git rev-list --left-right --count origin/main...main`：本地 main 落后 origin/main 11 个提交（之前会话已见此状态）。需先 `git pull --rebase` 把本地提交放在远端 11 个提交之上，否则推送会被拒绝

## 提交与推送

3. `git pull --rebase origin main`（若 `FontConfigHandler.ts`/`base.less` 与远端改动冲突，则停止并向用户报告，不强行覆盖）
4. `git add` 全部已修改文件（按用户指示“全部提交”，包括用户本地那两个文件一并纳入，提交前用 `git status` 复核清单）
5. `git commit` 提交信息：`🐛 修复更新弹窗上下重复显示同一份中文的问题（双语拆分 + 回填双语 CHANGELOG）`，遵循仓库现有 emoji 前缀风格（如 `🐛 修复…`、`✨ 修复…`）
6. `git push origin main`

## 不做的事

- 不修改任何文件内容（含尚未处理的“英文段缺标题”回归——那是在 plan mode 里讨论的另一项工作，本次仅按用户指示提交推送现有改动）
- 不强推、不 force push；若 rebase 冲突则停下报告

## 备注

- 远端 v0.0.1~v0.0.3 的 GitHub Release 正文已在上一轮通过 API 改为双语（服务端数据，不涉及本次 git 推送）
- `pnpm run compile`（扩展宿主）未跑——本轮仅改了 webview 与根目录文件；若想更稳妥，提交前可先跑一次，失败则先解决再推
